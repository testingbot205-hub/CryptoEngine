## 📝 Опис проєкту

**SecureMsg** — це кросплатформний десктопний застосунок для захищеного обміну повідомленнями та файлами. Програма реалізує гібридну криптографічну схему, що поєднує асиметричне шифрування **RSA-2048 (OAEP/SHA-256)** для захисту сесійних ключів та симетричне шифрування **AES-256-GCM** для шифрування даних з автентифікацією цілісності.

Програма має сучасний темний інтерфейс, побудований на **PyQt6**, і призначена для використання в корпоративному середовищі, зокрема в компанії **Weatherford Ukraine**.

## 🏗 Архітектура та технології

### Технологічний стек

| Компонент | Технологія | Версія |
|-----------|-----------|--------|
| GUI | PyQt6 | ≥ 6.6.0 |
| Криптографія | `cryptography` (Hazmat) | ≥ 42.0.0 |
| Мова | Python | 3.11+ |
| Формат даних | Бінарний (.smsg) | — |

### Криптографічні алгоритми

- **Асиметричне шифрування:** RSA-2048 з OAEP padding (SHA-256)
- **Симетричне шифрування:** AES-256-GCM
- **Nonce:** 96 біт (12 байт), випадковий
- **Тег автентифікації:** 128 біт (16 байт)

### Чому GCM, а не CBC?

- **CBC** шифрує дані, але **не автентифікує** їх — підробку файлу можна не помітити
- **GCM** = шифрування + MAC в одному проході. Будь-яка зміна шифротексту або заголовка виявляється при дешифруванні (`AuthenticationError`)

## 🚀 Використання

### Перший запуск

При першому запуску програма автоматично пропонує згенерувати пару ключів RSA-2048:

1. Відкриється діалог **«SecureMsg — перше налаштування»**
2. Опціонально встановіть пароль для захисту приватного ключа
3. Натисніть **OK** — ключі будуть збережені у `~/.securemsg/keys/`

> ⚠️ **Увага:** Якщо відмовитися від генерації ключів, програма завершить роботу.

### Шифрування тексту

1. Перейдіть на вкладку **🔒 Шифрування**
2. Оберіть отримувача зі списку контактів
3. Введіть текст у поле **«Текст для шифрування»**
4. Натисніть **🔒 Зашифрувати текст**
5. Результат у форматі Base64 з'явиться внизу
6. Скопіюйте результат (**📋 Копіювати результат**) або збережіть як `.smsg` файл (**💾 Зберегти як .smsg**)

### Шифрування файлів

1. На вкладці **🔒 Шифрування** натисніть **📂 Обрати файл**
2. Оберіть файл для шифрування
3. Натисніть **🔒 Зашифрувати файл**
4. Збережіть результат як `.smsg` файл

> Оригінальне ім'я файлу зберігається в зашифрованому пакеті.

### Дешифрування

#### Текст (Base64):
1. Перейдіть на вкладку **🔓 Дешифрування**
2. Вставте Base64-рядок у верхнє поле
3. Натисніть **🔓 Розшифрувати текст**
4. Якщо приватний ключ захищений паролем — введіть його

#### Файл (.smsg):
1. Натисніть **📂 Обрати .smsg** та оберіть файл
2. Натисніть **🔓 Розшифрувати файл**
3. Збережіть розшифрований файл

### Управління ключами та контактами

#### Мій публічний ключ
- Перейдіть на вкладку **🔑 Ключі та контакти**
- Ваш публічний ключ відображається у лівій колонці
- **📋 Копіювати ключ** — скопіювати у буфер обміну
- **💾 Зберегти .pem** — зберегти у файл для передачі колезі
- **🔄 Згенерувати нові ключі** — створити нову пару (увага: старі повідомлення стануть недоступними!)

#### Контакти
- **➕ Додати контакт** — вставити PEM-ключ колеги або завантажити з файлу
- **🗑 Видалити** — видалити обраний контакт
- **🔍 Переглянути ключ** — переглянути публічний ключ контакту
- **💾 Зберегти .pem** — експортувати ключ контакту у файл

## 🔐 Криптографічна схема

### Формат зашифрованого пакету (.smsg)

```
[4 bytes]   довжина зашифрованого AES-ключа (big-endian)
[N bytes]   зашифрований AES-ключ (RSA-OAEP)
[12 bytes]  nonce (AES-GCM)
[остаток]   шифротекст + 16-байтовий GCM-тег
```

### Формат файлового пакету (відкритий текст перед шифруванням)

```
[2 bytes]   довжина імені файлу (big-endian)
[N bytes]   ім'я файлу (UTF-8)
[остаток]   вміст файлу
```

### Алгоритм шифрування

1. Генерується випадковий 256-бітний AES-ключ сесії
2. AES-ключ шифрується RSA-OAEP публічним ключем отримувача
3. Відкритий текст шифрується AES-256-GCM з випадковим 96-бітним nonce
4. Упаковується у бінарний формат `.smsg`

### Алгоритм дешифрування

1. Розбір заголовка пакету
2. Розшифрування AES-ключа приватним ключем (RSA-OAEP)
3. Розшифрування даних AES-GCM з автоматичною перевіркою цілісності
4. Якщо тег не збігається — піднімається помилка автентифікації

## 🛡 Безпека

| Аспект | Реалізація |
|--------|-----------|
| **Захист приватного ключа** | Опціональне шифрування паролем (PKCS#8) |
| **Права доступу** | Приватний ключ: `0o600` (тільки власник) |
| **Сесійні ключі** | Одноразові, генеруються для кожного повідомлення |
| **Nonce** | Випадковий, 96 біт — рекомендований розмір для GCM |
| **Цілісність** | GCM-тег автоматично перевіряє підробку |
| **Пам'ять** | Пароль кешується тільки після успішної перевірки |

### Рекомендації з безпеки

- Використовуйте пароль для захисту приватного ключа в корпоративному середовищі
- Регулярно створюйте резервні копії приватного ключа (`my_private.pem`)
- Ніколи не передавайте приватний ключ третім особам
- Перевіряйте публічні ключі контактів перед додаванням
