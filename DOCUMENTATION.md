## 1. Загальний опис

**SecureMsg** — кросплатформний десктопний застосунок для захищеного обміну повідомленнями та файлами з використанням гібридного шифрування RSA-2048-OAEP + AES-256-GCM.

### Призначення

- Шифрування текстових повідомлень і файлів довільного розміру
- Передача зашифрованих даних через будь-який канал (email, месенджери, USB, хмарні сховища)
- Робота без серверної інфраструктури (zero server dependency)
- Захист комерційної інформації класифікації Restricted

### Цільова аудиторія

- Польові інженери нафтосервісних компаній
- Менеджери проєктів
- IT-адміністратори
- Будь-які користувачі, яким потрібна проста E2EE-передача даних

### 2.2. Паттерн проєктування

Використано спрощений паттерн **MVC (Model-View-Controller)**:

| Компонент | Файл | Відповідальність |
|-----------|------|------------------|
| **Model** | `crypto_engine.py`, `key_manager.py` | Бізнес-логіка, криптографія, управління даними |
| **View** | `main_window.py` (EncryptTab, DecryptTab, KeysTab, AboutTab) | Відображення інтерфейсу, прийом введення |
| **Controller** | `MainWindow` | Координація взаємодії між Model і View через сигнали Qt |

### 2.3. Потік даних

```
Шифрування тексту:
  Користувач вводить текст → EncryptTab → crypto_engine.encrypt_text()
  → RSA-OAEP(ключ сесії) + AES-GCM(дані) → .smsg пакет → Base64 → буфер обміну/файл

Шифрування файлу:
  Користувач обирає файл → EncryptTab → crypto_engine.encrypt_file()
  → [name_len][filename][content] → encrypt() → .smsg файл

Дешифрування:
  Користувач вставляє Base64 / обирає .smsg → DecryptTab → crypto_engine.decrypt()
  → RSA-OAEP розшифрування ключа → AES-GCM decrypt + verify tag → відкритий текст/файл
```

## 3. Модуль crypto_engine.py

### 3.1. Призначення

Криптографічне ядро програми. Реалізує гібридну схему шифрування та власний формат пакету `.smsg`. **Не має залежностей від GUI** — може використовуватись автономно.

### 3.2. Залежності

```python
import os
import struct
from cryptography.hazmat.primitives.asymmetric import rsa, padding
from cryptography.hazmat.primitives import hashes, serialization
from cryptography.hazmat.primitives.ciphers.aead import AESGCM
```

### 3.3. API Reference

#### `generate_key_pair() → tuple[RSAPrivateKey, RSAPublicKey]`

Генерує нову пару ключів RSA-2048.

| Параметр | Значення | Обґрунтування |
|----------|----------|---------------|
| `public_exponent` | 65537 (2¹⁶+1) | Стандарт FIPS 186-5, оптимальний для апаратної реалізації |
| `key_size` | 2048 біт | NIST SP 800-131A: прийнятний до 2030 року |

**Повертає:** `(private_key, public_key)` — об'єкти `cryptography`.

**Час виконання:** ~0.28 с на Intel Core i5-11400.

---

#### `serialize_private_key(private_key, password=None) → bytes`

Серіалізує приватний ключ у формат PEM (PKCS#8).

| Параметр | Тип | Опис |
|----------|-----|------|
| `private_key` | RSAPrivateKey | Приватний ключ |
| `password` | bytes \| None | Пароль для шифрування ключа (опціонально) |

**Повертає:** PEM-закодований ключ у вигляді `bytes`.

---

#### `serialize_public_key(public_key) → bytes`

Серіалізує публічний ключ у формат PEM (SubjectPublicKeyInfo).

**Повертає:** PEM-закодований публічний ключ.

---

#### `load_private_key(pem_data, password=None) → RSAPrivateKey`

Завантажує приватний ключ із PEM.

---

#### `load_public_key(pem_data) → RSAPublicKey`

Завантажує публічний ключ із PEM.

---

#### `encrypt(plaintext: bytes, recipient_public_key: RSAPublicKey) → bytes`

Основна функція шифрування. Реалізує гібридну схему.

**Алгоритм:**
1. Генерує одноразовий 256-бітний AES-ключ (`os.urandom(32)`)
2. Генерує одноразовий 96-бітний nonce (`os.urandom(12)`)
3. Шифрує AES-ключ RSA-2048-OAEP з SHA-256
4. Шифрує дані AES-256-GCM
5. Упаковує у формат .smsg

**Повертає:** Бінарний пакет `.smsg` (bytes).

**Приклад:**
```python
from crypto_engine import generate_key_pair, encrypt

priv, pub = generate_key_pair()
message = b"Конфіденційне повідомлення"
package = encrypt(message, pub)
```

---

#### `decrypt(package: bytes, private_key: RSAPrivateKey) → bytes`

Основна функція дешифрування.

**Алгоритм:**
1. Розбирає заголовок .smsg пакету
2. Розшифровує AES-ключ приватним RSA-ключем
3. Розшифровує дані AES-GCM з верифікацією MAC-тегу

**Винятки:**
- `ValueError("Неправильний ключ або пошкоджений пакет.")` — помилка RSA-OAEP
- `ValueError("Помилка автентифікації: файл пошкоджено або підроблено.")` — невідповідність GCM-тегу

**Приклад:**
```python
from crypto_engine import decrypt

try:
    plaintext = decrypt(package, priv)
    print(plaintext.decode("utf-8"))
except ValueError as e:
    print(f"Помилка: {e}")
```

---

#### `encrypt_text(text: str, recipient_public_key: RSAPublicKey) → bytes`

Зручна обгортка для шифрування тексту. Кодує UTF-8 → шифрує → повертає .smsg.

---

#### `decrypt_text(package: bytes, private_key: RSAPrivateKey) → str`

Зручна обгортка для дешифрування тексту. Дешифрує → декодує UTF-8.

---

#### `encrypt_file(file_path: str, recipient_public_key: RSAPublicKey) → bytes`

Шифрує файл зі збереженням імені.

**Формат відкритого тексту перед шифруванням:**
```
[2 bytes]  name_len (uint16 big-endian)
[N bytes]  filename (UTF-8)
[остаток]  file_content
```

**Повертає:** .smsg пакет.

---

#### `decrypt_file(package: bytes, private_key: RSAPrivateKey) → tuple[str, bytes]`

Дешифрує файловий пакет.

**Повертає:** `(filename, file_content)`

---

### 3.4. Криптографічні параметри

| Параметр | Значення | Стандарт |
|----------|----------|----------|
| Асиметричний алгоритм | RSA-2048-OAEP | NIST SP 800-131A |
| Хеш-функція OAEP | SHA-256 | FIPS 180-4 |
| MGF1 | SHA-256 | RFC 8017 |
| Симетричний алгоритм | AES-256-GCM | NIST SP 800-38D |
| Розмір nonce | 96 біт (12 байт) | NIST SP 800-38D §8.2.1 |
| Розмір MAC-тегу | 128 біт (16 байт) | NIST SP 800-38D §5.2.1.2 |
| Генерація випадкових чисел | os.urandom() | NIST SP 800-90A (CSPRNG) |

## 4. Модуль key_manager.py

### 4.1. Призначення

Управління криптографічними ключами та адресною книгою контактів. Відповідає за збереження, завантаження та організацію ключів на диску.

### 4.2. Структура директорій

```
~/.securemsg/
├── keys/
│   ├── my_private.pem     # Приватний ключ (права 0o600)
│   └── my_public.pem      # Публічний ключ (права 0o644)
└── contacts/
    ├── Ivan_Petrenko.pem  # Публічний ключ контакту
    ├── Client_ABC.pem
    └── ...
```

### 4.3. API Reference

#### `ensure_dirs()`

Створює директорії `~/.securemsg/keys/` та `~/.securemsg/contacts/`, якщо їх немає.

---

#### `has_own_keys() → bool`

Перевіряє наявність збереженої ключової пари.

---

#### `create_own_keys(password: str | None = None) → RSAPublicKey`

Генерує нову ключову пару і зберігає на диск.

| Параметр | Тип | Опис |
|----------|-----|------|
| `password` | str \| None | Пароль для шифрування приватного ключа |

**Дії:**
1. Генерує RSA-2048 пару через `crypto_engine.generate_key_pair()`
2. Серіалізує приватний ключ (з паролем або без)
3. Серіалізує публічний ключ
4. Зберігає у `~/.securemsg/keys/`
5. Встановлює права `0o600` на приватний ключ

**Повертає:** Публічний ключ.

---

#### `load_own_private_key(password: str | None = None) → RSAPrivateKey`

Завантажує власний приватний ключ.

**Винятки:** `ValueError("Неправильний пароль або пошкоджений ключ.")`

---

#### `load_own_public_key() → RSAPublicKey`

Завантажує власний публічний ключ.

---

#### `get_own_public_key_pem() → str`

Повертає публічний ключ у PEM для копіювання/передачі.

---

#### `save_contact(name: str, public_key_pem: str)`

Зберігає публічний ключ контакту.

---

#### `load_contact_key(name: str) → RSAPublicKey`

Завантажує публічний ключ контакту.

**Винятки:** `FileNotFoundError(f"Контакт «{name}» не знайдено.")`

---

#### `list_contacts() → list[str]`

Повертає відсортований список імен контактів.

---

#### `get_contact_pem(name: str) → str`

Повертає PEM-рядок публічного ключа контакту.

---

#### `delete_contact(name: str)`

Видаляє контакт.

---

#### `import_contact_from_file(name: str, file_path: str)`

Імпортує публічний ключ із файлу `.pem`.

**Дії:**
1. Читає файл
2. Перевіряє валідність ключа через `crypto_engine.load_public_key()`
3. Зберігає як контакт

## 7. Формат даних .smsg

### 7.1. Бінарна структура пакету

```
┌─────────────────────────────────────────────────────────────────────┐
│  [4 bytes]   key_len    │  uint32 big-endian                        │
│                         │  Довжина зашифрованого AES-ключа          │
├─────────────────────────────────────────────────────────────────────┤
│  [key_len]   enc_key    │  RSA-2048-OAEP(sha256)                      │
│                         │  Зашифрований 256-бітний AES-ключ сесії   │
├─────────────────────────────────────────────────────────────────────┤
│  [12 bytes]  nonce      │  Випадковий 96-бітний nonce AES-GCM       │
├─────────────────────────────────────────────────────────────────────┤
│  [M bytes]   ciphertext│  AES-256-GCM(plaintext) + 16-byte MAC tag  │
│              + tag      │  (tag додається автоматично AESGCM)       │
└─────────────────────────────────────────────────────────────────────┘
```

**Оверхед:** 4 + 256 + 12 + 16 = **288 байт** на пакет (незалежно від розміру даних).

### 7.2. Структура відкритого тексту для файлів

Перед шифруванням файл упаковується:

```
┌─────────────────────────────────────────────────────────────────────┐
│  [2 bytes]   name_len   │  uint16 big-endian                        │
│                         │  Довжина імені файлу в UTF-8              │
├─────────────────────────────────────────────────────────────────────┤
```

## 9. Інструкція з використання

### 9.1. Перший запуск

1. Запустіть програму: `python main.py`
2. Відкриється діалог «Першого налаштування»
3. Опціонально встановіть пароль для приватного ключа
4. Натисніть **OK** — ключі згенеруються автоматично

### 9.2. Обмін ключами

1. Перейдіть на вкладку **«Ключі та контакти»**
2. Скопіюйте свій публічний ключ (**📋 Копіювати ключ**)
3. Надішліть ключ колезі через будь-який канал
4. Отримайте публічний ключ колеги
5. Натисніть **➕ Додати контакт** і вставте ключ

### 9.3. Шифрування тексту

1. Перейдіть на вкладку **«Шифрування»**
2. Оберіть отримувача зі списку
3. Введіть текст
4. Натисніть **🔒 Зашифрувати текст**
5. Скопіюйте Base64-результат або збережіть як `.smsg`

### 9.4. Шифрування файлу

1. На вкладці **«Шифрування»** натисніть **📂 Обрати файл**
2. Оберіть файл
3. Натисніть **🔒 Зашифрувати файл**
4. Збережіть `.smsg` файл

### 9.5. Дешифрування

1. Перейдіть на вкладку **«Дешифрування»**
2. Вставте Base64-рядок або оберіть `.smsg` файл
3. Натисніть **🔓 Розшифрувати**
4. При потребі введіть пароль приватного ключа

## 11. Відомі обмеження та перспективи

### 11.1. Поточні обмеження

| Обмеження | Опис | Обхід |
|-----------|------|-------|
| Відсутність цифрового підпису | Отримувач не може верифікувати відправника | Передача ключів через захищений канал |
| Відсутність PKI | Ручний обмін ключами | Корпоративний IT-адміністратор розповсюджує ключі |
| Chunked processing | Файли >200 МБ завантажуються в пам'ять | Розбивати на частини або використовувати CLI |
| CLI-версія | Лише GUI | Можливість розробити окремий CLI-модуль |

### 11.2. Перспективи розвитку

1. **Постквантова криптографія** — перехід на ML-KEM (Kyber) при появі загрози
2. **Цифровий підпис** — RSA-PSS або Ed25519 для автентифікації відправника
3. **PKI на базі X.509** — автоматичне управління ключами
4. **CLI-версія** — для автоматизації та CI/CD
5. **Мобільний клієнт** — Android/iOS з підтримкою .smsg
